## Docker Images: 
    we have dockerfile: it contains a set of instructions on how to build a docker image.
    docker image is the result of building a docker file `docker build -t my-node-app .`
        reads the dockerfile
        executes each instruction line by line
        Packages everything (Node + your app + dependencies) into a single image.
    docker container is the running instance of a docker image: `docker run -d -p 3000:3000 my-node-app`
        this command starts a new container from the image: my-node-app
        runs it in detached mode (-d)
        maps port of our machine 3000 to the port of the container 3000 (-p 3000:3000)

    dockerfile -> build -> docker image -> run the image -> docker containers

    question) so for every image, do I need to write specific dockerfile..?
    ans) no, you can directly pull the image using docker pull, 
        now lets understand how can we do this: 
        - docker login : use this command in docker cli(terminal).. and provide your dockerHub credentials.. and login into it
        - give username: as your docker hub username
        - give password as: your dockerhub password  or generate a personal access token and use it
        - once logged in: 
            - docker pull hello-world
            - docker images
            - docker run hello-world
            the above commands will first the public image: hello world into my docker images, then docker images command will let us see what images do we have in
            docker images section, and then we will run the hello-world image.. which will create the container and we can see the output
            - docker run hello-world: this command is equivalent to docker pull + docker run image.. if image is not present locally, it will download that image
            and run that image...
            - similarly we can download multiple images: for eg: mysql.. use docker pull mysql
                - and then we can run sql commands under its container
                - for running mysql we use: docker run -e MYSQL_ROOT_PASSWORD=root mysql, 
                    since my sql is a server, 
                    we use docker run command using the environment variable as MYSQL ROOT PASSWORD = someValue.. and run the server
                    environment variable (-e) is provided using -e, and then we provide the env variable such as MYSQL_ROOT_PASSWORD=root 
                    mysql has started

    question) how do we come out of the screen, when the container is running, for eg.. we are inside mysql container..?
    ans) whenever we run a container, it blocks the screen or terminal.. so for that we can do two things: 
        1) we can run the container in detached mode using -d tag.. 
            docker run -d -e MYSQL_ROOT_PASSWORD=root mysql
        2) we can again connect to the aws instance.. and go to cd/downloads and start a new instance:
            then we can say: docker stop <docker_container_id>, this will stop the container.. and we can see the terminal is unblocked by sql or any other
            container

## Docker Networking: 
    whats the need of docker networking? 
    ans: suppose we have two docker containers, for eg. a python app container and mysql container. 
        then if we want the two containers to communicate with each other we would be needing a bridge to connect those two containers. 
        and that bridge is known as Docker network. 
        without the network, the two containers cannot communicate to each other. 

    Types of Docker Network: 
        Host 
        Bridge (Default)
        User defined bridge (Custom)
        None 

        Other typs [OUTDATED]: (Generally studied with docker swarm, which is not used much now. Docker swarm is replaced by KUBERNETES)
        MACVLAN (docker swarm)
        IPVLAN
        Overlay

    Docker network commands: 
        docker network ls: lists the docker networks currently active 
        docker network create <custom_network_name> -d bridge: creates a user defined network of type(driver) bridge. [here -d means driver/type of network]
            Now if you do, `docker network ls`: it will list all the current networks including the network, which you have created just now.

## Docker Volumes and Storage: 
    Lets understand this with the help of eg. 
    if we have two containers 'mysql' and 'two-tier-flask' both connected via a docker network 'two-tier-network'
    Ideally, whatever data we are storing via application using 'two-tier-flask' app, its storing in our 'mysql' container database = 'devops'
    so now if we do:
        docker stop <mysql_container_Id> && docker stop <mysql_container_id> : // it will stop the mysql container and delete it.
        and then again if we do: 
            docker run -d --name mysql --network two-tier -e MYSQL_ROOT_PASSWORD=root -e MYSQL_DATABASE=devops mysql : // it will again start a fresh container
            docker restart <two-tier-flask-container-id>: // stops and start the two-tier-flask container so that we can have the fresh connection
                but the problem is: all the data which we have stored in the backend via 'two-tier-flask' app using ipv4 public address:5000 is all gone.. mysql is created newly, no backup of the older data
                ** THIS IS WHERE DOCKER VOLUMES COMES INTO THE PICTURE ** 
    
    Problem: 
        what if our database or any data related container crashes.. all the data would be gone.. we dont able to fetch the data again if we create a new data related container such as 'mysql' container 
    Solution: 
        we use docker volumes for that, we map the local host path (here in case of ec2: ubuntu is the host) with data coming from container in our local host. 
        so with this, data will persist in our local host as well. so everytime we create a fresh container, we only need to tell the container to: 
            use my host data location as your docker volume storage.. so that container can able to access the already existing data

        Lets see it in action: [ CREATING A DOCKER VOLUME ] [WAY: 01]
            docker volume ls: // lists all the docker volumes currently available in the system. 
            docker volume create mysql-data : // creates a custom docker volume with name mysql-data 
            docker inspect mysql-data: // this is to check where my volume is created in the host[ubuntu], check 'Mountpoint' value. you will see something like: '/var/lib/docker/volumes/mysql-data/_data'

        Now I want to bind my 'mysql-data' volume with the 'mysql' container: 
            docker stop 'mysql_container_Id' && docker rm 'mysql_container_Id': // delete 'mysql' containers if any, just for the better understanding. 
            docker run -d --name mysql --network two-tier -v mysql-data:/var/lib/mysql -e MYSQL_ROOT_PASSWORD=root -e MYSQL_DATABASE=devops mysql:
                // -v flag is used for mapping the 'volume created in the host' with the 'mysql data' in the container 
                // -v mysql-data:/var/lib/mysql : uses the docker volume created in the host = mysql-data and maps it with the container's path/volume where data needs to be mapped, 
                    In containers, the mysql data is stored at path: /var/lib/mysql, so we are mapping our volume(mysql-data) to that path. 
            docker restart <two-tier-flask-container-id>: // stops and start the two-tier-flask container so that we can have the fresh connection
                So now if you stop and delete this mysql container.. and again create the mysql container with the same mapping: 
                the data wont delete, you will see the same data you saw before. but not forget to restart the two-tier-flask container so that we can see the latest changes. 

        To check the real data in our host [ubuntu]: 
            cd /var/lib/docker/volumes/mysql-data/_data : // go to mountpoint/path of the volume which you have created 
                if the above command gives error: permission denied, use the command:=> sudo su : // get the super user permission, and then hit the above command again 
            you'll see that we have all the mysql files with our created database with name = 'devops'

        [ONE MORE WAY OF CREATING A VOLUME] [WAY: 02]
        Create the directory where you want to store the data, and copy the whole path in the docker -v command.. then the data will be mapped with the container's data 
        Lets see how: 
            docker stop 'mysql_container_Id' && docker rm 'mysql_container_Id': // delete 'mysql' containers if any, just for the better understanding.
            ubuntu@ip/projects/two-tier-flask-app$ mkdir volumes 
            ubuntu@ip/projects/two-tier-flask-app$ cd volumes 
            ubuntu@ip/projects/two-tier-flask-app/volumes$ mkdir mysql 
            ubuntu@ip/projects/two-tier-flask-app/volumes$ cd mysql 
            ubuntu@ip/projects/two-tier-flask-app/volumes/mysql$ pwd 
            /home/ubuntu/volumes/mysql 

                Now you can use the above host path in your container creation command and the data will persist.
                    here's how to use that command: 
                    docker run -d --name mysql --network two-tier -v /home/ubuntu/volumes/mysql:/var/lib/mysql -e MYSQL_ROOT_PASSWORD=root -e MYSQL_DATABASE=devops mysql

    
    NOTE: WE BASICALLY MAP OUR LOCAL HOST PATH TO THE CONTAINER'S DATA STORAGE PATH, SO THAT OUR DATA SHOULD PERSIST. SHOULD NOT GET LOST AFTER THE CONTAINER CRASHES OR DELETED

## Docker Compose: 
    Docker compose is used to automate the docker workflows. 
    It is a configuration file i.e, .yml/.yaml file.
    It is used to create the containers using a simple .yml/.yaml file
        rather than writing: docker build and run commands again and again to run the containers, we will use docker compose, that will build and run multiple containers.. using a single command. 
    
    Install docker compose: 
        sudo apt-get install docker-compose-v2: // this is to install docker compose 

    Lets create a docker compose file from scratch: 
        clone two-tier-flask-app, if not already cloned
        cd two-tier-flask-app: // navigate to two-tier-flask-app 
        ls: // lists all the contents in the repo. 
        rm -v docker-compose.yml: // remove existing docker compose file, we will create from the scratch
        vim docker-compose.yml: // create and open the docker-compose file in vim editor 
            Below are the two docker compose files:
            DOCKER FILE 1: 
                version: "3.8"
                services:
                    mysql:
                        image: mysql
                        container_name: mysql
                        environment:
                            MYSQL_ROOT_PASSWORD: root
                            MYSQL_DATABASE: devops
                            MYSQL_USER: admin
                            MYSQL_PASSWORD: admin
                        volumes:
                            - ./mysql-data:/var/lib/mysql
                        networks:
                            - two-tier
                        healthcheck:
                            test: ["CMD", "mysqladmin", "ping", "-h", "localhost", "-uroot", "-proot"]
                            interval: 10s
                            timeout: 5s
                            retries: 5
                            start_period: 60s

                    flask-app:
                        image: two-tier-flask-app:latest
                        container_name: flask-app
                        ports:
                            - "5000:5000"
                        environment:
                            MYSQL_HOST: mysql
                            MYSQL_USER: root
                            MYSQL_PASSWORD: root
                            MYSQL_DB: devops
                        depends_on:
                            - mysql
                        networks:
                            - two-tier
                        restart: always
                        healthcheck:
                            test: ["CMD-SHELL", "curl -f http://localhost:5000/health || exit 1"]
                            interval: 10s
                            timeout: 5s
                            retries: 5
                            start_period: 30s

                networks:
                    two-tier:       
            `THE ABOVE FILE USES THE ALREADY BUILT IMAGE 'two-tier-flask-app:latest' USING DOCKER BUILD, TO CREATE AND RUN THE FLASK-APP CONTAINER`                                                               

            DOCKER FILE 2: 
                // The other way.. for flask image we can use is build image directly from docker compose using, rather than using already built/existing image:     
                `build:		`
                `      context: . `

                In the below docker compose.yml file: 
                    flask-app:

                            context: .

                            - "5000:5000"
                        environment:
                            MYSQL_HOST: mysql

                            MYSQL_DB: devops
                        depends_on:
                            - mysql
                        networks:
                            - two-tier

                            test: ["CMD-SHELL", "curl -f http://localhost:5000/health || exit 1"]

                    Note: but for this you have to first switch to super user using `sudo su`

        docker run <image-name> => creates and starts a container from an image with image name = <image_name>
        docker run -d <image-name> => run the container in the background

                    * Disk size = 15G ✅
                    * Root partition = 7G ❌
                    * Filesystem = 6.8G ❌
                This is why df -h still shows 100% usage.

            Fix: Extend root partition + filesystem (SAFE)
            You are on Ubuntu, root is /dev/nvme0n1p1.
            Step 1: Grow the partition
                Use growpart (already available on Ubuntu EC2).
                    sudo growpart /dev/nvme0n1 1 : // this command is used to grow the partition size 
                Expected output (example):
                CHANGED: partition=1 start=2048 old: size=... new: size=...

            Step 2: Resize the filesystem
                Ubuntu root filesystem is ext4, so run:
                    sudo resize2fs /dev/nvme0n1p1 : // to resize the filesystem to match the new partition size 
                This expands / to use the full partition.

            Step 3: Verify
                df -h: // shows disk usage in human readable format. ( df means disk free )
            You should now see something like:
                Filesystem      Size  Used Avail Use%
                /dev/root        15G   7G    7G   ~50%

                * Increases disk size
                * ❌ Does NOT auto-expand partitions or filesystems

                    3. Extend filesystem
