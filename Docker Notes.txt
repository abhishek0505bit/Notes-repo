## Docker Images: 
    we have dockerfile: it contains a set of instructions on how to build a docker image.
    docker image is the result of building a docker file `docker build -t my-node-app .`
        reads the dockerfile
        executes each instruction line by line
        Packages everything (Node + your app + dependencies) into a single image.
    docker container is the running instance of a docker image: `docker run -d -p 3000:3000 my-node-app`
        this command starts a new container from the image: my-node-app
        runs it in detached mode (-d)
        maps port of our machine 3000 to the port of the container 3000 (-p 3000:3000)

    dockerfile -> build -> docker image -> run the image -> docker containers

    question) so for every image, do I need to write specific dockerfile..?
    ans) no, you can directly pull the image using docker pull, 
        now lets understand how can we do this: 
        - docker login : use this command in docker cli(terminal).. and provide your dockerHub credentials.. and login into it
        - give username: as your docker hub username
        - give password as: your dockerhub password  or generate a personal access token and use it
        - once logged in: 
            - docker pull hello-world
            - docker images
            - docker run hello-world
            the above commands will first the public image: hello world into my docker images, then docker images command will let us see what images do we have in
            docker images section, and then we will run the hello-world image.. which will create the container and we can see the output
            - docker run hello-world: this command is equivalent to docker pull + docker run image.. if image is not present locally, it will download that image
            and run that image...
            - similarly we can download multiple images: for eg: mysql.. use docker pull mysql
                - and then we can run sql commands under its container
                - for running mysql we use: docker run -e MYSQL_ROOT_PASSWORD=root mysql, 
                    since my sql is a server, 
                    we use docker run command using the environment variable as MYSQL ROOT PASSWORD = someValue.. and run the server
                    environment variable (-e) is provided using -e, and then we provide the env variable such as MYSQL_ROOT_PASSWORD=root 
                    mysql has started

    question) how do we come out of the screen, when the container is running, for eg.. we are inside mysql container..?
    ans) whenever we run a container, it blocks the screen or terminal.. so for that we can do two things: 
        1) we can run the container in detached mode using -d tag.. 
            docker run -d -e MYSQL_ROOT_PASSWORD=root mysql
        2) we can again connect to the aws instance.. and go to cd/downloads and start a new instance:
            then we can say: docker stop <docker_container_id>, this will stop the container.. and we can see the terminal is unblocked by sql or any other
            container

            UNDERSTANDING DOCKER FILE: 
                FROM: use to pull images which will give all required tools and libraries, eg: FROM openjdk:17-jdk-alpine
                WORKDIR: directory where the application will run on the container. eg: WORKDIR /app
                COPY: use to copy the content from host to container. eg: COPY . . // this means we are copying everything from host to container
                RUN: this is used to run any command, not to run the application. eg: RUN javac src/Main.java //this compiles main.java file 
                CMD: this is used to execute or run the application. eg: CMD ["java", "Main"], but in your case: ["java", "-cp", "src", "Main"], if Main class
                    is in /src folder of /app directory

                    we have similar command to CMD to run the app i.e, ENTRYPOINT. Difference is: 
                        CMD can be overridded, while running the docker run command in the terminal 
                        ENTRYPOINT can't be overridded, while running the docker run command in the terminal 

        - similarly we will create the python docker file using FROM, WORKDIR, RUN AND CMD 
            after creating the Dockerfile for python.

            But its not opening: why? 
            Because we haven't defined the inbound rules for this instance. meaning our port 80 is not available for everyone
            To define the inbound rules( means the incoming traffic to this url): 
                Go to our instance -> Security -> Security Groups -> Inbound rules -> Edit inbound Rules -> Add Rule 
                Give type: custom TCP 
                Port Range: 80 
                Source: Anywhere (can be accessed by anyone)
                Save Rules
            Now Refresh, your application will work.

## Docker Networking: 
    whats the need of docker networking? 
    ans: suppose we have two docker containers, for eg. a python app container and mysql container. 
        then if we want the two containers to communicate with each other we would be needing a bridge to connect those two containers. 
        and that bridge is known as Docker network. 
        without the network, the two containers cannot communicate to each other. 

    Types of Docker Network: 
        Host 
        Bridge (Default)
        User defined bridge (Custom)
        None 

        Other typs [OUTDATED]: (Generally studied with docker swarm, which is not used much now. Docker swarm is replaced by KUBERNETES)
        MACVLAN (docker swarm)
        IPVLAN
        Overlay

    Docker network commands: 
        docker network ls: lists the docker networks currently active 
        docker network create <custom_network_name> -d bridge: creates a user defined network of type(driver) bridge. [here -d means driver/type of network]
            Now if you do, `docker network ls`: it will list all the current networks including the network, which you have created just now. 
        
    Now we will do a project on docker networking: 
        clone the two-tier-flask-app from github/londheshubham153
        Inside the running ec2 instance: 
            git clone <https_repo_url>

            now lets see: do we have anything which is required to run this app:

            Now we will build the image for the two-tier-flask-app and run it: 
                docker build -t two-tier-backend . : builds the docker image using docker file in the current directory using the tag as `two-tier-backend`
                docker run -d -p 5000:5000 -e MYSQL_HOST=mysql -e MYSQL_USER=root -e MYSQL_ROOT_PASSWORD=root -e MYSQL_DB=devops two-tier-backend:latest :
                    The above command will run a container with : 
                        - docker image two-tier-backend which has latest tag.

                        - publishes the port no. 5000 of the host to port 5000 of the container. // so when the container runs, we can see the outcome in port no. 5000
                        - having env variables:
                            MYSQL_HOST = mysql // MYSQL_HOST=mysql, we can give the host name = container name such that if we already have a container with name 'mysql'
                            MYSQL_USER = root

Note: under MYSQL_HOST = <mysql_container_name> [Here: mysql]
                docker ps: lists all the active containers 
                    now we can see that our mysql as well as two-tier-backend:latest containers are running

                    we see the logs with no error. tells that our container is running perfectly fine

### IMPORTANT DOCKER COMMANDS: 
    ## IMAGES: 
        docker build -t <image-name> . : to build an image using the Dockerfile. `.` is context, that means Dockerfile is kept in the current dir❗️
        docker build -t <image-nname> . -no-cache : to build an image from docker file using docker file without cache
        docker images: List local images ❗️
        docker rmi <image-id>/<image-name> : delete an image ❗️
        docker image prune: Remove all unused images

    ## CONTAINERS: 
        docker run <image-name> => creates and starts a container from an image with image name = <image_name>
        docker run -d <image-name> => run the container in the background
        // Question? what is the diff bw container running in the background and container running on terminal..? 
            ans-> 'docker run image-name' => it runs the container and closes it.. 
                to keep the docker container running, we should use: 'docker run -itd <image-name>/<image-id>'.[so now when you do 'docker ps', you will see the container for this image running]

        docker run -p <hostPort>:<containerPort> <imageName> => Run a container and map host port to the container port.. 
        docker start/stop <container-id>/<container-name> => start/stop the existing container
        docker rm <container-name>/<conatainer-id> => remove the stopped container 
        docker exec -it <container-name> sh => open a shell inside a running container 
            for eg. we have mysql container running with id: mysql id: 
            then: docker exec -it mysqlId bash
                //bash opened in the mysql container 
                bash-5.1# mysql -u root -p 
                Enter password: root
                then it says: welcome to mysql, your sql starts working
        docker run -itd <image-name>/<image-id> => to keep the container running in the background. it doesn't close the container after running. You can see this cotainner running using 'docker ps' command 
        docker ps => to list the currently running containers
        docker ps -a => list all containers whether running or stopped 
        docker log <container-id> => to see the logs in the container 
        docker attach <containner-id> => to see the logs LIVE. docker gets attached to the terminal.. [To come out of it, open one more terminal and ssh inside it using ssh -i command of aws, then type =>  docker stop <container-id>/<container-name>]

    
    ## DOCKER HUB: 
        docker login -u username => Login To docker 
        docker push <username>/<image-name> => push an image to dockerhub.. eg. docker push johndoe/my-repo:latest
        docker pull <image-name> => pull an image from docker hub 

    ## DOCKER NETWORK: 
        docker network ls: shows all the active networks 
        docker network create two-tier -d bridge: create a new custom docker network of driver/type bridge 
        docker run -d --name mysql --network two-tier -e MYSQL_ROOT_PASSWORD=root -e MYSQL_DATABASE=devops mysql: creates and starts a container with image name = mysql with the network = two-tier, and with the provided env variables
